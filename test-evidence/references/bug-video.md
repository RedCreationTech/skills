# 缺陷复现与标注

## 何时算缺陷

满足以下任一条件才登记为缺陷：

- 实际结果与用例预期不一致，且可复现。
- 关键业务约束缺失（如电子签名、权限校验、审计记录）并可实际观察到。
- 数据在提交或重新读取后不一致。

仅影响观感、文案或无法确认预期的情况记为**观察项**，不计入缺陷数；需要产品确认时在报告中单列。

## 复现视频的最小内容

1. 环境与实例号（画面或顶部标注带）。
2. 角色与入口。
3. 触发缺陷的最短操作路径。
4. 实际结果（提示、列表变化、审计详情）。
5. 预期结果（顶部标注带的“预期”一行）。
6. 可核对的辅助证据：审计记录、日志、重新打开后的状态。

不要只录一个错误弹窗；要让人看懂“怎么走到这里”和“为什么这是错的”。

## 标注规范

使用 `scripts/annotate.py`，输入一份 JSON：

```json
{
  "title": "文件借阅复测 · 出错位置精确标注",
  "right": "实例 demo-001 · 缺陷 BUG-01",
  "note": "红框=出错/核对位置；编号=当前时间段说明",
  "marks": [
    {
      "start": 50.0,
      "end": 57.0,
      "box": [930, 110, 170, 44],
      "label": "1",
      "text": "点击删除后直接提示成功，未弹出电子签名"
    },
    {
      "start": 76.0,
      "end": 83.0,
      "box": [395, 480, 650, 200],
      "label": "2",
      "text": "电子签名页仅显示 SM3，签名人和时间为暂无数据"
    }
  ]
}
```

```bash
python3 scripts/annotate.py --video evidence/raw-bug.webm \
  --spec evidence/bug-marks.json --output out/bug-annotated.mp4 \
  --font "/System/Library/Fonts/Supplemental/Arial Unicode.ttf"
```

坐标基于原始视频画面，不含顶部标注带；脚本会整体下移标注带高度。每个编号只标一个位置，红框不要遮挡关键文字；编号圆点放在框外空白处。

## 级别与报告

| 级别 | 判定建议 |
|---|---|
| 阻塞 | 主流程无法继续、数据损坏、权限或签名完全失效 |
| 严重 | 关键合规/审计能力缺失，但有临时绕行方式 |
| 一般 | 局部功能错误、提示不一致、可恢复的数据展示问题 |
| 轻微 | 文案、样式、非关键交互问题 |
| 观察项 | 预期未确认，暂不计缺陷 |

BUG 清单必须包含：编号、级别、模块、标题、对应用例 ID、前置条件、复现步骤、实际结果、预期结果、证据时间点、状态、修复建议。视频时间点使用成片时间，不用原始录制时间。

## 修复后回归

修复后重录同一路径，保留修复前视频作为对照；如果无法安全复现旧版本，明确说明只有修复后证据。回归结论写“通过/仍失败/未验证”，不要把“代码已改”当成已验证。
