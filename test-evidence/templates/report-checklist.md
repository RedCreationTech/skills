# 测试报告交付检查

填表前后逐项核对，全部满足才算完成。

## 数字

- [ ] 用例总数 = 通过 + 失败 + 阻塞 + 未执行。
- [ ] 覆盖表每一行的合计等于该行分项之和。
- [ ] 文字里的“未执行场景数”与表格口径一致，并写明是“用例”还是“场景组”。
- [ ] BUG 清单条数 = 报告缺陷条数；观察项单列，不计入缺陷数。
- [ ] 每个失败用例都能在 BUG 清单和证据索引中找到对应项。
- [ ] 缺陷按级别统计的合计等于缺陷总数。

## 环境与范围

- [ ] 被测地址、构建号/版本、测试日期、环境类型已填写。
- [ ] 账号与角色只写必要信息，不写密码、令牌和真实客户数据。
- [ ] 预置数据、模拟接口、外部依赖和未覆盖范围已明确说明。
- [ ] 执行轮次与修复后回归范围已记录。

## 结论

- [ ] 存在阻塞缺陷时结论不是“通过”。
- [ ] 存在严重缺陷时结论为“有条件通过”或“不通过”，并写明条件。
- [ ] 结论没有“基本通过”“应该没问题”等无法审计的措辞。
- [ ] 后续动作（修复、回归、上线建议）与缺陷级别匹配。

## 证据

- [ ] 证据索引列出成片、原始录屏、截图、`test-run.json`、SRT 和章节时间。
- [ ] 视频时间点使用成片时间，并已人工抽查开头、关键操作、失败和结尾。
- [ ] `verify.py` 无 FAIL；警告项已逐条确认。
- [ ] 报告中引用的“通过”都有实际断言，未执行项没有被算成通过。

## 文档

- [ ] 模板中的示例项目名、旧数字、旧结论已全部替换。
- [ ] 表格没有跨页断裂，页眉页脚和页码正确。
- [ ] 中文、符号和日期格式统一；导出 PDF 抽查无缺字。
- [ ] 文件名、版本号和变更记录符合项目规范。
